# Git版本管理+Claude Code开发 高频实操指令手册
## 前言
目前工作经常会基于Qt/Python进行自动化程序项目开发，使用的工具搭配如下：

| 工具类型   | 工具名 |
|--------|---|
| 集成开发环境 |Pycharm|
| 编程语言   |Python|
| 版本管理工具 |Git|
| 开发AI工具 |Claude Code|

让AI辅助参与开发是目前常见的开发方式，Claude Code作为一个强劲好用的开发助手，已大规模投入到企业的日常项目开发进程中，然而，AI本质还是语言预测模型，难免会有幻觉现象，
难免会遇到一个新的需求喂给AI后，发现AI直接把程序改出了严重BUG，打乱了原本的代码框架，甚至直接无法运行，因此一个代码版本管理工具十分重要，可以在关键时刻一键回滚我们的项目文件和代码。
虽然Claude自带/rewind 回退功能可以还原聊天记录和代码，但还是建议采用目前最主流的版本管理工具：Git。Git支持多版本管理，可以自由创建版本分支，支持新旧代码的合并，
可以自由管理哪些文件纳入目前的版本管理，个人认为是十分好用的。 Git原本是在终端用命令行CLI进行交互的，交互体验来说不太友好，所以建议一般搭配Pycharm、VS Code等集成开发程序进行使用，
这些集成开发环境专门为Git适配了可视化交互，支持点击式操作进行版本管理，非常好用，不过有些时候还是需要我们手动执行命令去操作Git。在开始之前，还是要对Git有一些基础认知：
在项目根目录下，如果我们要进行版本管理，可以在Pycharm中打开这个项目，然后在Git分区点击创建Git仓库，Git就会在项目根目录自动创建一个.git目录，这个目录就会记录此项目后续所有的版本管理信息。
在Git中，一般以“分支”为单位进行开发，一个分支可以对应多个版本记录。比如：我新建一个Git仓库，想要开发一个产品寿命-失效率预测程序，可以先写一个产品框架雏形的版本，这里称这个分支为main分支，
之后我想要往里添加新的功能，比如说导出分析报告，那么就可以在当前分支新建分支features，在这个新分支中专门开发我们的新功能。开发新功能时可能产生了10条提交记录，开发完毕后，features分支的指针默认
会指向最新的提交记录，经过测试后发现新功能正常运行没有bug，我们就可以将新功能代码和老版本的main分支代码进行合并，具体流程就是先“签出”到main分支，然后将features分支合并到main分支，其中的代码可以以features为主进行保留。
Git的基本用法介绍完毕， 接下来本手册会尽量摒弃冷门命令，只保留日常开发会用到的高频操作命令进行展示，附带案例、报错解决、避坑说明，基本可直接复制运行，方便需要时进行查找使用。

## 一、Git 核心实操指令
### 1. 分支操作
```
# 1. 查看所有本地分支（带当前指向）
git branch

# 2. 切换分支（例如：切到老备份分支shixiaolv）
git checkout 分支名

# 3. 新建并切换新分支
git checkout -b 新分支名

# 4. 让备份分支跟随最新代码
# 案例：把 shixiaolv 指针强制移动到当前最新提交（不产生新提交）
git branch -f shixiaolv HEAD

# 5. 合并分支（案例：把旧分支代码合并进主线，需要先签出到合并后想要作为主线的分支也就是原本的主线中）
git merge 旧版本分支

# 6. 合并出错/想撤销合并（兜底救命命令）
git merge --abort
```
### 2. 提交 & 暂存 & 查看日志
```
# 1. 查看当前代码变更状态
git status

# 2. 全部添加到暂存区
git add .

# 3. 提交代码（附带代码备注）
git commit -m "feat: 新增xxx功能"

# 4. 查看可视化分支时间线（最强排查命令，专治分支看不到、不知道指向哪）
git log --oneline --graph --decorate --all

# 5. 临时储藏修改（不想提交、临时切分支必备）
git stash
# 恢复储藏的代码
git stash pop
```
### 3. 取消文件/文件夹版本跟踪（你当前核心需求，解决中文文件、文件夹报错）
已经提交过的文件，`.gitignore` 单独无效，必须配合 git rm --cached，只取消跟踪、不删除本地文件，`.gitignore`只适用于忽略还未加入版本管理的文件。
```
# 【单文件取消跟踪｜中文路径专用】目录包含中文建议加双引号
git rm --cached "kekaoducode/可靠度计算.py"

# 【文件夹取消跟踪｜高频】必须加 -r 递归（否则 fatal:not removing 报错）
# 案例1：取消整个kekaoducode文件夹跟踪
git rm --cached -r kekaoducode/

# 案例2：取消中文文件夹 tkinter框架代码 跟踪
git rm --cached -r "tkinter框架代码/"

# 【批量取消】一次性多个目录/文件
git rm --cached -r kekaoducode/ "tkinter框架代码/" xiugai.py

# 【验证是否取消成功】查看当前所有被Git跟踪的文件
git ls-files
```
需要注意`git ls-files`指令得到的结果可能不会显示中文，中文名文件在git中会用八进制数据存储，显示为类似"\234"的代码，在终端中运行git指令还是需要用文件原本的实际中文名，所以这里就需要自行判断
到底是哪些文件需要移除版本管理。在pycharm中，移除了一些文件的版本管理后需要在git管理分区勾选更新过的文件（删除后一般会变灰），然后进行一次提交，git才不会继续跟踪这些文件的变动。
### 4. .gitignore 规范配置
写入根目录.gitignore，提交后永久生效
```
# 忽略单个文件
main.py
main.ui
# 忽略整个文件夹
code/
tkinter/
# 忽略一类后缀文件
*.log
*.bak
*.tmp
# 缓存、编译文件
__pycache__/
build/
dist/
```
### 5. 版本回退（保命指令，谨慎使用）
```
# 1. 软回退：撤销上次提交，代码保留在本地（最安全）
git reset --soft HEAD~1

# 2. 硬回退：彻底回退到某个版本，清空本地改动（慎用！）
git reset --hard 【commit哈希值】

# 3. 分支强制同步（案例：把当前分支完全覆盖成shixiaolv旧版本）
git reset --hard shixiaolv
```
### 6. 差异对比（合并前预判冲突）
```commandline
# 对比当前分支和shixiaolv分支所有差异
git diff shixiaolv

# 对比指定单个文件差异
git diff shixiaolv -- code/main.py
```

## 三、 Git开发范式推荐:Git Flow 分支管理 + 原子化提交 + 分层迭代开发
一下方式兼顾单人开发、后续团队协作。
## 1. 固定5类长期分支（永久存在）
1. `main`（主线/生产分支）：**永远只存放可交付、稳定无bug的版本**，禁止直接在该分支写代码，仅通过merge合并release/hotfix分支；每一次合并到main必须打版本标签 `vX.Y.Z`（如v1.2.0）。
2. `develop`（开发主分支）：所有新功能集成分支，存放迭代完成、测试通过的功能，是日常开发核心分支；稳定积累到一定功能后合并进main发布版本。

## 2. 3类临时短期分支（开发完成即删除）
1. `feature/xxx` 功能分支：从develop拉出，单功能独立开发
   - 示例：`feature/shuidou_pulse_calc` 水道脉动计算UI、`feature/beta_query_btn` beta参数查询功能；
   - 规则：一个需求/一个工具对应一条feature分支，开发+自测完成后合并回develop，随后删除分支。
2. `release/vX.Y.Z` 版本发布分支：从develop拉出，统一做全量集成测试、文档完善、打包导出；测试无bug后合并main+develop，打版本标签。
3. `hotfix/vX.Y.Z` 紧急修复分支：线上main版本发现严重bug时，从main拉出，修复后同步合并main+develop，用于线上紧急补丁。

## 3. 强制原子化提交规范（每条提交只做一件事）
### 提交日志标准模板（固定格式，可读性拉满）
【类型】[模块] 简短描述（关联任务 ID）
详细补充说明（可选，换行写）

类型分类：
- feat：新增功能；fix：bug修复；opt：性能/UI逻辑优化；docs：文档更新；refactor：代码重构；test：单元/集成测试；chore：工程配置清理（删除无用文件、目录整理）

### 正确提交示例
1. feat [ShuidaoTool] 新增水道脉动次数计算UI界面（TASK-037）
2. opt [ShixiaolvTool] 统一导出报告默认文件名datahuang（TASK-036）
3. fix [ReliabilityTool] 修复quantity不参与失效率连乘计算bug（BUG-012）
4. chore [工程] 移除项目内无用冗余文件
